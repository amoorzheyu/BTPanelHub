# BTPanelHub

Chrome / Chromium Manifest V3 扩展，在工具栏 Popup 中本地管理多台宝塔面板。

## 开发

Node.js 24+，执行 `npm ci`、`npm run dev`，打开开发服务的 `/popup.html`。普通网页只用于界面开发，浏览器能力必须加载扩展验证。

执行 `npm run build`，在 Chrome 的 `chrome://extensions` 开启开发者模式，选择“加载已解压的扩展程序”，选择本项目 `dist` 目录。更新构建后点击扩展卡片的刷新按钮。

执行 `npm test` 运行核心逻辑测试。

## 数据与权限

配置与凭据仅存于 `chrome.storage.local`。本地存储不是系统密码保险柜；可选站点权限仅用于主动启用的自动登录。仅打开面板不要求站点权限。导出默认排除密码，带密码的备份应妥善保管。验证码、MFA、未知登录页需要手动操作。

原始设计资料位于被 Git 忽略的 `docs/`，测试凭据不包含在源码和构建产物中。

## 使用

- 用右上角加号新建目录或服务器；目录菜单提供子目录、新增、移动、排序和批量打开。
- 打开按钮每次新建标签，同一服务器复用标签组；多个服务器即使同名也分别分组。
- 开启服务器自动登录后，首次打开会申请对应站点权限；全局填充、提交与延迟可在设置调整。验证码、动态口令、未知页面保留手动处理。
- 任务在后台运行，关闭 Popup 后仍会执行，重新打开可查看结果；取消只影响待执行项，失败项可单项或批量重试。
- 设置中导入 JSON 前会预览冲突；合并会保留未被备份包含的现有密码，覆盖会完整替换配置。导出默认不包含密码。

运行 `npm run package` 会重新构建并生成 `release/BTPanelHub-0.1.0.zip`。该命令需要系统提供 `zip`，macOS 默认可用。压缩包解压后可作为未打包扩展加载。

Popup 按 Chrome 限制固定为 420×600，长表单和设置在内部滚动。开发页面仅用于 UI 检查，真实标签、权限和自动登录应使用已加载扩展验证。

## 会话失效恢复

已保存并授予站点访问权限的面板，在原标签出现简洁的 nginx `404 Not Found` 页面时，会自动返回该服务器保存的完整安全入口 URL。页面加载、切换标签以及后台检查都会触发检测，已打开的旧标签也适用，无需从扩展重新打开。

返回入口后，若已有会话则直接保留面板；若需要登录，会按服务器自动登录与全局填充/提交设置处理。验证码、动态口令和无法识别的页面会停止自动操作，结果记录在“会话恢复”任务中。为避免入口失效导致循环，同一标签两分钟内最多自动返回入口一次，安全入口自身的 404 不再重定向。

检测仅限已配置入口的相同协议、主机和端口，不为任意网站的 404 页面跳转。同一地址配置了多个不同入口时，优先使用标签原有的服务器关联；没有可靠关联则不猜测账号。没有站点权限时不会注入检测脚本，可在设置中授权该服务器的站点。
